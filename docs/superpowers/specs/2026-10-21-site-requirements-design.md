## ① 画面と URL

| URL | 画面 | 内容 |
|---|---|---|
| `/` | トップ | 「新規作成」ボタン、検索欄、キャラクターの一覧 |
| `/characters/new` | 新規作成 | シートの入力欄とパスワード欄。保存すると詳細へ移る |
| `/characters/:id` | 詳細 | 閲覧専用。誰でも見られる |
| `/characters/:id/edit` | 編集 | 誰でも開ける。保存するときにパスワードを入力する。保存すると詳細へ移る |

### トップページ

- 一覧の列: キャラクター名、PL名、クラス、タイプ、レベル
- クラスとタイプはルールブックの表記（カタカナ）のまま表示する
- 並び順: 作成が新しい順
- 行をクリックすると詳細へ移る
- 各行に「編集」「複製」ボタンを置く。ボタンのクリックは行のクリックとして扱わない
- 削除の操作は用意しない

### 複製

1. 行の「複製」ボタンを押すと、パスワード入力のダイアログが開く
2. 送信すると Functions が複製元のパスワードを照合し、複製先を作る。複製先のパスワードは複製元と同じになる
3. 成功したらダイアログを閉じ、トップページに戻って一覧を読み込み直す
4. パスワードが違うなどで失敗したら、ダイアログの中にエラーを表示する。ダイアログは閉じない

### 保存（新規作成・編集）

- 新規作成ではパスワードの入力を必須にする。空のパスワードは受け付けない
- 編集では、保存ボタンを押したときにパスワードを入力する。照合に失敗したらエラーを表示し、入力した内容はそのまま残す

## ② インクリメンタルサーチ

- トップページを開いたときに、`characterSummaries` を全部読み込み、クライアント側で絞り込む
- 検索の対象: キャラクター名、PL名、クラス、タイプ。部分一致で、大文字と小文字は区別しない
- 入力するたびに絞り込む
- 想定している規模は数百件程度まで。それを超えたら作り直す

## ③ データとパスワード

### Firestore のコレクション

| パス | 中身 | クライアントの読み込み | クライアントの書き込み |
|---|---|---|---|
| `characters/{id}` | シート本体（`{ sheet }`） | 許可 | 拒否 |
| `characterSummaries/{id}` | 一覧用の項目と作成日時（`createdAt`） | 許可 | 拒否 |
| `characterSecrets/{id}` | パスワードのハッシュとソルト | 拒否 | 拒否 |

- 3 つのコレクションは同じ ID を使う
- 一覧用の項目（キャラクター名、PL名、クラス、タイプ、レベル）は別のコレクションに置く。Firestore の Web SDK はドキュメントの一部のフィールドだけを読めないので、トップページでシート本体まで読み込まずに済むようにするため（#6 で変更）

### 書き込み用の Functions（callable、`asia-northeast1`）

| 関数 | 入力 | 動作 |
|---|---|---|
| `createCharacter` | シート、パスワード | ハッシュを作り、3 つのコレクションを 1 つのバッチで書く。新しい ID を返す |
| `updateCharacter` | ID、シート、パスワード | 照合してから `characters` と `characterSummaries` を上書きする（`createdAt` は変えない） |
| `duplicateCharacter` | ID、パスワード | 照合してから 3 つのコレクションを新しい ID でコピーする。`createdAt` は複製した日時にする。新しい ID を返す |

- 書き込みには Admin SDK を使う。Firestore ルールは通らない
- 入力は Functions 側でも Schema で検証する
- パスワードが違うときは `permission-denied`、キャラクターがないときは `not-found` を返す
- ハッシュは `node:crypto` の scrypt を使い、キャラクターごとにランダムなソルトを付ける。比較には `timingSafeEqual` を使う
- パスワードの変更と、忘れたときの復旧は用意しない。忘れたときは管理者が Firestore を直接操作する

### あえて作らないもの

- パスワードを総当たりされたときの対策（レート制限、App Check）。必要になったら別 Issue にする
- ページング、並び順の切り替え

## ④ 環境とデプロイ

| 環境 | Firebase プロジェクト | `.firebaserc` の alias | デプロイのきっかけ |
|---|---|---|---|
| ローカル | `demo-ryutama`（Emulator） | `default` | なし |
| 開発 | 開発用の実プロジェクト | `dev` | `main` に push したとき |
| 本番 | 本番用の実プロジェクト | `prod` | GitHub で Release を公開したとき（`release: published`） |

- 開発環境と本番環境は別々の Firebase プロジェクトにする。データも分ける
- どちらも Blaze プランにする（Functions を使うため）
- プロジェクト ID は、プロジェクトを作る Issue で決めて `.firebaserc` に書く
- Web の Firebase 設定は、環境ごとにビルド時の env（`VITE_FIREBASE_*`）で渡す
- デプロイには GitHub Actions を使う。認証情報は GitHub の Environment（`dev`、`prod`）ごとに Secret として登録する
